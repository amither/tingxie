# 儿童英语听写 PWA 设计文档

日期：2026-11-10

## 目标

为 7 岁儿童做一个在 iPad 上运行的英语单词听写应用。纯前端 PWA，无后台、无外部调用，尽量使用 iOS 本地能力。

## 范围

做：
1. 通过拍照或 PDF 导入最近学过的单词（英文 + 中文词义）。
2. 听写：显示中文词义，孩子在输入框里手写英文，提交后判对错。错误时朗读单词，正确时自动进入下一个。
3. 用遗忘曲线（简化 Leitner 盒子）调整单词出现频率。

不做：
- 句子听写（导入时忽略句子区）。
- 账号、云同步、多孩子档案。

## 已验证的前提

- 手写输入使用 iOS 系统能力：简体中文“手写”键盘（手指）或 Scribble（Apple Pencil），在普通 `<input>` 中使用。已用测试页在 iPad 上验证，上屏顺畅，符合预期。
- 输入框设置 `autocapitalize="off" autocorrect="off" autocomplete="off" spellcheck="false"`。
- 判题：`trim()`、合并连续空格、转小写后与答案全等比对。

## 架构

原生 JS（ES modules），无构建步骤。Service Worker 缓存全部资源，包括 pdf.js、Tesseract.js 及其 `eng`、`chi_sim` 语言包，首次加载后离线可用。数据存 IndexedDB，并请求 `navigator.storage.persist()`。添加到主屏幕后全屏运行。

| 模块 | 职责 | 依赖 |
|---|---|---|
| `store` | IndexedDB 读写词条与设置；导出/导入 JSON 备份 | 无 |
| `scheduler` | 纯函数：根据答题结果计算新盒子与到期时间；挑选本轮词 | 无 |
| `parser` | 纯函数：把一行文字拆成 英文 / 词性 / 中文 | 无 |
| `importer` | 照片/PDF → 文字 → 词条草稿 | pdf.js、Tesseract、parser |
| `speech` | 封装 `speechSynthesis`，选择 en-US 语音 | 浏览器 |
| `ui` | 首页、导入校对页、听写页、词表页、设置页 | 以上全部 |

## 数据模型

词条：`{ id, en, zh, batch, box(0–5), dueAt, reps, lapses, createdAt, firstSeenAt }`。`firstSeenAt` 为首次答题时间，初始 `null`；`null` 表示新词，并用于统计“今天已出现的新词数”。

设置：`{ sessionSize: 10, newPerDay: 5 }`（家长可改，每轮词数可选 5/10/20）。

## 记忆算法

盒子间隔：0 → 立即；1 → 1 天；2 → 3 天；3 → 7 天；4 → 14 天；5 → 30 天。

- 第一次就写对：盒子 +1，`dueAt` = 今天 + 对应间隔，`reps` +1。
- 写错：盒子归 0，`lapses` +1，该词在本轮末尾再次出现，直到写对。
- 重试后才写对：盒子保持 0，`dueAt` 设为明天。
- 选词顺序：先取新词，每天最多 `newPerDay` 个，且不超过每轮词数；新词优先取最近导入的批次，批内按导入顺序。名额有剩余时再用已到期词补（盒子低的优先，同盒子按过期时间）。
- 新词直接进入听写，不设单独的学习环节。

## 界面

适配 iPad 横竖屏，字大、按钮大。

1. **首页**：“开始听写”大按钮；显示今天到期词数和可补新词数；入口：导入、词表、设置。无词时引导去导入。显示距上次备份的天数，超过 14 天提醒导出。
2. **听写页**：顶部进度（如 3/10）；中间大号中文词义，旁有“听发音”按钮；输入框自动聚焦；“提交”按钮。
   - 写对：显示绿色 ✓，约 0.8 秒后自动进入下一个。
   - 写错：显示红色 ✗ 和正确拼写，自动朗读，孩子点“知道了”后继续；该词排到本轮末尾。
   - 本轮结束：显示答对数和需要多练的词，按钮“再来一轮”“回首页”。
3. **导入页**：选择“拍照”或“选 PDF”，识别后进入校对页。
   - 校对页为可编辑列表：每行英文/中文，可改、可删、可新增；填写批次名（默认取文件名或日期）。
   - 与已有词（英文相同）重复的行会标出，默认跳过，可选“覆盖中文”。
   - 未能解析的行单独标为“未识别”，由家长补全或删除。
   - 点“保存”才写入。
4. **词表页**：按批次分组；可改、删；显示盒子和下次出现时间；可把某词“重置为新词”。
5. **设置页**：每轮词数、每天新词上限、测试发音、导出/导入备份。

## 导入流程

- **PDF**：pdf.js 先取文字层；内容足够就直接解析。取不到（扫描版）就把页面渲染成图片，走拍照同样的 OCR 流程。
- **拍照**：图片做灰度和对比度增强，再用 Tesseract（`eng+chi_sim`）识别。
- **解析**：按行处理，切出英文、词性（`n.`、`adv.` 等，丢弃）、中文；表格左右两栏分别处理。中文词义里的括号内容保留（如“脚（复数）”）。“Sentences”区域整块忽略；一行中英文含句号、问号，或词数超过 3 个，视为句子丢弃。两个词的短语（如 `pencil case`、`hardly ever`）保留。

样本：Koala English “Paper Check — First grammar&writing — Lesson 8”（斜拍屏幕照片，双栏表格）。

## 错误处理

- OCR/PDF 失败：提示“没识别出内容”，允许手动逐条添加。
- 手写输入出现汉字或符号：直接判错，正常显示正确答案。
- 没有英文语音：设置页“测试发音”提示去 iPad 设置下载英文语音。
- 存储被系统清理的风险：靠定期导出备份缓解。

## 测试

- `scheduler`、`parser` 用 Node 自带 `node:test` 做单元测试，不引入框架。`parser` 的用例取自 Lesson 8 样本。
- UI 与 OCR 在 iPad 上人工验证，实现阶段提供检查清单。

## 待实测的风险

- 斜拍屏幕照片的 OCR 准确率（靠校对页兜底）。
- 真实 PDF 是否带文字层（拿到文件后确认，决定默认走哪条路径）。
